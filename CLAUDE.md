# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`mm-compare` is a React 17 (CRA/`react-scripts`) single-page app that compares Fuzzy Cognitive Map
(FCM) models exported from Mental Modeler (`.mmp` files, JSON or legacy XML). A user loads several
candidate models, designates one as the "canonical"/reference model, runs a comparison, and views
per-model and aggregate diff results (matching/non-matching concepts and linkages, structural
metrics) with an xlsx export.

All model parsing, comparison, and metrics logic lives in a **sibling local package**, `mm-modules`
(`file:../mm-modules`, imported as the `mm-modules` package). This repo only contains the UI and
state management; do not reimplement comparison/parsing logic here — it belongs in `../mm-modules`.
See `../mm-modules/CLAUDE.md` for that package's domain model and module responsibilities
(`loadAndParse`, `compareModels`, `getMetrics`, etc.) if you need to understand or change how
comparisons are computed.

## Commands

```bash
npm start       # build CSS once, then watch Less + run react-scripts dev server
npm run build   # build CSS, build JS (react-scripts build), then move build/ -> docs/
npm run deploy  # build, then git add/commit/push docs/ to main (publishes via GitHub Pages)
npm test        # build CSS, then react-scripts test --env=jsdom
```

- `npm run build-css` / `npm run watch-css` run `node-less-chokidar` over `src`, compiling each
  component's `.less` file to a co-located `.css` (+ `.css.map`) file that the component imports
  directly (e.g. `Models.less` -> `Models.css`, imported by `Models.js`). Edit the `.less` source,
  not the generated `.css`.
- There is no separate lint script; linting runs through CRA's built-in `eslint-config-react-app`
  during build/test.
- To run a single test file, use the underlying CRA test runner directly, e.g.
  `npx react-scripts test --env=jsdom path/to/File.test.js`.
- `docs/` is the built-site output committed to the repo (GitHub Pages serves from it per
  `homepage` in `package.json`); it is regenerated by `npm run build`/`deploy`, not hand-edited.
- `mm-modules` must exist as a sibling directory (`../mm-modules`) for `npm install`/`file:` linking
  to resolve.

## State architecture

All app state lives in a single `useReducer` in `App.js` (`src/components/App/App.js`), reduced by
`appReducer` (`src/appReducer.js`), and shared via `AppContext` (`React.createContext`). There is no
Redux/external store — `setState` (the reducer dispatch) is passed through context as `setState`
and `dispatch` (same function, two names in context value).

Two ways components update state, both go through the same reducer:
- **Direct merge**: `setState({ someKey: value })` — shallow-merged into state as-is (e.g. switching
  `mode`, toggling `showConfigureColumns`).
- **Action dispatch**: `setState({ action: { type: '...', ...payload } })` (often called via the
  `dispatch` alias for clarity) — handled explicitly in `appReducer.js`'s `if (action.type === ...)`
  chain. Current action types: `addJSON`, `removeModel`, `compare`, `updateScenario`, `columnShown`.
  Add new action types as another `else if` branch in `appReducer.js`, not as ad hoc state merges,
  if the update needs derived/computed logic (compare, id generation, etc.).

Key state shape (see initial `useReducer` call in `App.js`): `modelsJSON` (array of loaded/parsed
models, each with a generated `id`), `canonicalId` (id of the reference model), `results` (keyed by
model id, populated by the `compare` action calling `mm-modules`' `compareModels`), `mode`
(`'files' | 'scenario' | 'result' | 'results'`, controls which panel renders in `App.js`'s `<main>`),
`viewResultId` (which model's result the `Result` panel shows), `columnsShown` (checkbox state for
which metric columns `ResultsAll` displays).

`mode === 'scenario'` / the `Scenario` component and `updateScenario` action represent a scenario
simulation feature that is **currently disabled** — the code to initialize/run a scenario is
commented out in `App.js` and `appReducer.js` (see the "not running the scenario anymore" comment).
Don't assume `Scenario` is live without checking whether it's actually reachable from `Controls`.

## Component structure (`src/components/`)

- **App** — owns the reducer/context, top-level layout (header with `Controls`, main area that
  switches on `mode`).
- **Controls** — header buttons: load files (`<input type="file" multiple>` -> `mm-modules`'
  `loadAndParse` per file -> `addJSON` dispatch), trigger `compare`, switch to `results` mode, plus
  a dev-only "Copy state JSON" button gated by `isDevEnv()`.
- **Models** — lists loaded models as cards; set a model as canonical ("Reference"), remove a model,
  or jump to its individual result view.
- **Result** — single-model diff view (`Overlay`-wrapped): matching/non-matching concepts and
  linkages for one model vs. the canonical, derived from `results[viewResultId]`'s
  `nodes`/`relationships` shape (`present`/`missing`/`extra`/`reversed`/`correctlySigned`/
  `incorrectlySigned`).
- **ResultsAll** — aggregate table across all compared models; `columnsAll` defines every available
  metric column (each with a `key` and a `display(result)` renderer) filtered by `columnsShown`;
  includes a configure-columns toggle panel and xlsx export (via `xlsx`, serializing the rendered
  `.ResultsAll__table` DOM table with `XLSX.utils.table_to_sheet`).
- **Overlay** — generic modal/panel wrapper used by `Result` and `ResultsAll`.
- **Scenario** / **ScenarioRow** — scenario-configuration UI; currently unreachable/disabled (see
  above).

`src/json/*.json` are sample saved-state fixtures (not loaded in production); `App.js` dev-loads one
of them (`steven_state_results.json`) via `useEffect` when `isDevEnv()` is true, to speed up manual
testing without re-loading `.mmp` files each time. Swap which `import json from ...` line is active
to test against a different fixture.

`mmp/` at the repo root holds sample `.mmp` model files (JSON/XML) used for manual testing of the
load/compare flow, grouped by scenario (`test001`, `fish_wetland`, `for_compare`).
